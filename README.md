# WakaranAI — 宿題を、答え合わせで終わらせない。

従来の画面デザインを維持し、「授業 → 宿題 → 誤答分析 → 先生の指導 → 後日の個別復習」へ変更した、ハッカソン用の操作可能なプロトタイプです。

## 開く

通常モードの自由記述をGroq APIへ接続しました。画面デザイン・問題・出題構造は維持しています。依存ライブラリのインストールは不要です。Node.js 22以上（推奨24）を使用し、APIキーを設定してからサーバー経由で開いてください。HTMLを直接開く方法ではAPI通信できません。

```powershell
node server.cjs
```

http://127.0.0.1:4173 を開いてください。終了は起動したターミナルで Ctrl+C。ポート変更は `$env:PORT=4174` を設定してから起動します。

## 新しい体験

1. **先生が設定**：「先生の確認」→「宿題を設定」。単元・合計問題数（3〜10問）・提出期限を選択します。一次方程式と連立方程式、それぞれ10種類の問題を用意しています。
2. **生徒が回答**：正解なら問題終了。不正解・未解答のときだけ、4つの小さな質問で前提スキルを確認します。
3. **宿題を提出**：通常問題の正答数、分析結果、回答原文を先生画面へ反映します。分析の問題は宿題の正答数に混ぜません。
4. **翌日の確認**：スキル別の人数、生徒別の結果、確認候補と根拠を表示します。スキルの人数を押すと対象生徒を絞り込めます。
5. **学校で先生が指導**：生徒本人と確認し、指導メモを残して「指導済みにする」を押します。ここでは定着確認にしません。
6. **次の宿題へ自動反映**：指導済みの生徒は、例えば連立方程式8問＋等式の性質の復習2問。他の生徒は連立方程式10問。配布前に生徒ごとの内訳を確認できます。
7. **復習で確認**：対象スキルの復習2問が両方正解で、宿題を提出したら「定着確認」。1問でも不正解・未確認なら「要指導（確認候補）」へ戻します。

初期状態では、体験用の3人に一次方程式3問を設定しています。「生徒を切り替え」で康さん・田中さん・佐藤さんを操作できます。追加した宿題は既存の宿題を消さず、選択欄や履歴から取り組みを再開できます。

## 状態の意味

| 状態 | 更新タイミング |
| --- | --- |
| 回答を確認 | 通常の問題や分析質問で正答したとき。長期的な定着を意味しない |
| 要指導（確認候補） | 誤答の分析結果を提出、または復習で確認できなかったとき |
| 指導済み・要再確認 | 学校で指導した先生が押したとき |
| 定着確認 | 指導後の別の宿題で、復習2問に正解して提出したとき |

分析は確認候補であり、原因を確定する診断ではありません。「定着確認」も、このプロトタイプでは復習2問を満たした記録を指します。

## 発表用デモ

1. 右上の「デモを見る」→「サンプルを開く」。通常の宿題とは別の保存領域で動きます。
2. 康さんが一次方程式 **3問中2問正解**。等式の性質は2人、分配法則は1人が確認候補です。
3. 康さんの根拠「6を反対側に持っていけばいいから」を確認し、指導メモを入力します。
4. 「✓ 指導済みにする」を押します。黄色の「指導済み・要再確認」になり、緑にはなりません。
5. 「宿題を設定」で連立方程式・10問・翌週の期限を選びます。康さんは **通常8問＋復習2問**、他の生徒は通常10問です。
6. 配布すると康さんの宿題が開きます。初回の連立方程式の解は順に `(x,y) = (3,2), (4,1), (2,3), (5,2), (1,4), (4,3), (6,1), (2,5)` です。
7. 復習の1問目は `5`。2問目の回答例は次です。

   「左右は同じ値だから、両辺に同じ操作をすると等しさが保たれる。」

8. 最後に宿題を提出すると、「指導済み・要再確認 → 定着確認」を表示します。

短い発表では、配布前の「8問＋2問」を見せた後、問題数を3問にすると「通常1問＋復習2問」で同じ流れを実演できます。

「デモを終了」で通常の宿題に戻ります。もう一度「デモを見る」からサンプルを開くと、発表用データだけを最初から作り直します。

## 復習を割り当てるルール

- 「指導済み・要再確認」のスキルだけが対象です。
- 指導日より後の提出期限の、新しい宿題に2問を追加します。
- 1回につき1スキル。複数あれば指導日時が古いものを優先し、残りは次回以降へ持ち越します。
- 合計問題数は維持します。10問なら8＋2、3問なら1＋2。復習がなければすべて通常問題です。
- 既に未提出の宿題に割り当てた復習は、重複して配布しません。
- 新しいつまずきが記録された場合、以前に割り当てた古い復習の正答だけで、その新しいつまずきを定着確認にはしません。
- 発表で日付を待たずに一周できるよう、将来の期限の宿題もすぐ解けます。実際の経過日数による受験制限・定着研究の判定はありません。

## 現時点の範囲

**通常モードの分析質問・復習問題の自由記述を、Groqの openai/gpt-oss-120b で分析します。** 発表用デモは固定ルールのままでAPI通信しません。数値・数式も既存のプログラム判定です。「まだ分からない」ボタンは本人の申告として記録します。AIの結果も確認候補であり、先生が原文を確認してください。数式は限定した記法に対応し、任意の数式の同値性判定は行いません。

生徒・先生画面の共有は同一ブラウザ内です。バックエンドDB、認証、別端末への実送信、クラウド公開は未実装です。データはブラウザ保存領域に残り、ブラウザデータを削除すると消えます。通常と発表用サンプルは別々に保存します。旧版の保存キー `wakaranai-v1` は変更・削除せず、新版の宿題履歴には移行しません。

旧仕様にあった指導直後の出口チェックは、後日の宿題での個別復習に置き換えています。競合調査は今回の画面・フロー変更には含めていません。

- `index.html`：アプリの入口
- `style.css`：既存デザイン＋宿題設定・先生一覧の追加スタイル
- `engine.js`：問題、採点、宿題、分析、指導・復習の状態管理
- `app.js`：画面描画、操作、ブラウザ保存
- `server.cjs`：ローカル専用配信とGroq APIへの中継
- `test.cjs`：状態遷移・採点・割当て・保存・描画の検証

```powershell

```

テストは仮のAPI応答とローカル通信だけを使い、実際のGroqへは通信しません。実APIでの接続・日本語判定精度は、キー設定後に架空の回答で確認してください。

## APIキーの設定（Windows PowerShell）

キーはファイルに書かず、サーバーを起動するPowerShellの環境変数 `GROQ_API_KEY` に入れます。
Groq Consoleで発行したキーをチャットやGitHubへ貼らないでください。
下のコマンドを、このREADMEのあるフォルダーで実行してください。

```powershell
& {
  Read-Host 'Groqのキー本体をコピーしてから、ここに戻ってEnterを押してください'
  $copiedKey = Get-Clipboard -Raw
  if ([string]::IsNullOrWhiteSpace($copiedKey) -or $copiedKey.Trim() -notmatch '^[\x21-\x7E]+$') {
    Write-Host 'キーをコピーし直してください。'
    return
  }
  $env:GROQ_API_KEY = $copiedKey.Trim()
  Remove-Variable copiedKey
  node server.cjs
}
```

先にコマンド全体を実行し、待機表示が出たらGroqでキー本体をコピーします。PowerShellに戻ってEnterだけを押してください。キーをターミナルへ貼り付ける必要はありません。キーそのものをコマンドに直接書かないので、コマンド履歴へも残しません。
設定はこのPowerShellとそこから起動するサーバーに渡ります。ウィンドウを閉じたら、次回は再設定してください。
追加の.envファイルは不要で、server.cjsは.envを自動読込しません。

起動後に http://127.0.0.1:4173 を開きます。すでに開いていたら再読み込みしてください。
「Groq API: 設定済み」はキーの存在を示すだけで、有効性・接続成功を確認した表示ではありません。
停止はCtrl+C。共有・圧縮するファイルにキーを含めないでください。

## 最初の接続確認

通常モードの未回答の最初の一次方程式で、わざと99と回答します。
分析を開始し、最初の問題なら「3x+6」「9」「3」と回答すると、4番目に理由の自由記述が出ます。
例：「左右は同じ値だから、両辺に同じ操作をすると等しさが保たれる。」
この回答の送信時だけAPI通信します。別の問題では、その問題に対応する数値を入力してください。
キー未設定・通信失敗・制限超過では評価を記録せず、入力を残します。同じ送信ボタンから再送できます。
通信中は送信・切替操作を一時停止し、返答先が変わっていないことも検査します。
復習の自由記述も同じ接続を使います。接続テストは実在の子どもの個人情報を使わず行ってください。

## 生徒・先生の入口

起動時に「生徒としてはじめる」か「先生としてはじめる」を選びます。「入口に戻る」で切り替えます。生徒画面では宿題・理解マップ・学習の記録、先生画面では確認・指導・宿題設定を利用できます。画面の区別でありログイン認証ではありません。デモは先生画面から始まります。生徒の宿題を試す場合は入口から生徒画面へ移動してください。
